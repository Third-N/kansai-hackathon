# 道中（仮題）

旅程のリアルタイム再最適化。放置RPGの体裁をとっている。
デモ用の操作パネルは入っていない。実時計で動く。

```bash
npm install
npm run dev        # http://localhost:3000
npm run typecheck
npm test           # 契約テスト + スキーマ・権限テスト（55本）
```

Supabase を設定しなければ localStorage 実装で動く。設定は `.env.example` を参照。

## 画面

| ルート | 中身 |
|---|---|
| `/` | ホーム。道中にもどる／出立／合流／前の道中 |
| `/plan?mode=solo\|party` | 行き先えらび |
| `/party/[code]` | 待合。あいことば、参加者、出発 |
| `/trip/[id]` | 道中。ゲージ、双六の道程、割り込み |
| `/trip/[id]/decide/[roundId]` | せーの。伏せる → カウントダウン → 一斉開示 |
| `/trip/[id]/log` | 道中記。終わってから見る |
| `/host/[id]` | ホスト画面。大画面・幹事端末用。全画面で開く |

## 担当の境界

### A（UI・演出）— このリポジトリの現状
- `components/` と `app/` の見た目、`app/globals.css` のトークン
- 触ってよい。ロジックの入出力の形は変えない

### B（Realtime・状態）— 実装済み

`TripStore` の実装が2つある。UI は `store` しか触らないので、切り替えても一行も変わらない。

| ファイル | 中身 |
|---|---|
| `lib/store-contract.ts` | 契約。`TripStore` と `CALL_BUDGET` |
| `lib/store.local.ts` | localStorage 実装。既定。開発と単機デモ用 |
| `lib/store.supabase.ts` | Supabase 実装 |
| `lib/store.deferred.ts` | 遅延読み込みの包み。使わない人に supabase-js を配らないため |
| `lib/store.ts` | どちらを使うか決めるだけ。UI が触るのはここ |
| `lib/supabase-like.ts` | 使うメソッドだけを写した型。テストで差し替えるための一枚 |
| `lib/storage.ts` | localStorage の置き場。SSR とテストではメモリに落ちる |
| `supabase/migrations/0001_init.sql` | テーブル・RLS・RPC |
| `supabase/migrations/0002_rooms.sql` | 待合の寿命・定員・権限・本人確認 |
| `supabase/migrations/0003_grants.sql` | 既定で付いてしまう GRANT を剥がす |

**環境変数が両方あれば Supabase、無ければ localStorage。** 判定は `lib/store.ts` の1箇所だけ。
`storeKind` で今どちらが動いているか取れる。

#### Supabase を用意する

1. プロジェクトを作る
2. SQL Editor に `supabase/migrations/` の SQL を**番号順に**貼って実行する
3. **Authentication → Providers → Anonymous sign-ins を有効にする**（下記）
4. `.env.local` に `NEXT_PUBLIC_SUPABASE_URL` と `NEXT_PUBLIC_SUPABASE_ANON_KEY` を書く

Realtime の publication はマイグレーションの中で設定するので、ダッシュボードでの操作は要らない。

#### 匿名ログインを有効にするかどうかで、守れるものが変わる

参加者IDは端末が名乗るだけなので、それだけでは本人確認にならない。
匿名ログインを入れると Supabase が端末ごとに ID を発行し、SQL 側が `auth.uid()` と
突き合わせられるようになる。

| | 有効にした場合 | しない場合 |
|---|---|---|
| 他人になりすまして投票する | できない | **できる** |
| 自分が入っていない道中を読む | できない | **できる**（anon キーがあれば） |
| あいことばを知らずに参加者になる | できない | できない |
| 他人の道程・呼び出し回数を書き換える | できない | できない |

**下2つはどちらでも塞がっている**（参加も書き込みも RPC の中だけを通るため）。
上2つが匿名ログイン次第。デモの前に有効にしておくこと。

#### 待合（ルーム）の作り

- **あいことばはサーバーで採番する。** 語 × 3桁で 12000 通り。衝突したら
  サーバーの中で取り直す。クライアントに「何回か試して駄目なら諦める」を持たせない
- **あいことばは開いている部屋の中だけで一意。** 終わった部屋は番号を手放す。
  全期間ユニークだと、通算で語数×桁数だけ作った時点で新しい部屋が作れなくなる
- **部屋には寿命がある**（既定12時間）。切れたら閉じ、あいことばが次の組に回る。
  掃除は `create_trip` / `join_by_code` のたびに走るので cron は要らない
- **定員は12人。**「デモの本番は5〜7人で」に対する上限側の歯止め
- **幹事は待合を閉じられる**（`setRoomLocked`）。閉じると新しい人は入れない
- **開き直しても名前は上書きされない。** 待合を再訪するたびに幹事が「旅人」に
  なるのを防ぐ
- **端末は複数の道中に入れる。** 参加者の主キーは `(trip_id, id)`

#### 守っている約束

- **票は誰にも読めない。** `vetoes` と `submissions` には権限を1つも与えていない。
  読めない・書けない・消せない。触れるのは `security definer` の RPC の中だけ。
  「UIで隠す」のではなく、読む手段そのものを与えていない
- **開示は冪等。** `reveal_round` は開示済みなら何もせず返し、開示時刻より前でも何もしない。
  誰の端末から呼んでもよい。幹事が落ちても、購読している誰かが時刻超過を見つけて呼ぶ
- **カウントダウンはサーバー時刻。** `reveal_at` は `open_round` RPC が `now()` から決める。
  開いた端末の時計のずれを全員に配らないため
- **決めきれないときの選び手は乱数ではない。** `round_tiebreak(round_id)` で決める。
  `Math.random()` だと、冪等なはずの2回目の開示で別の案が勝ちうる
- **書き込みは全部 RPC の中。** `trips` / `members` / `rounds` にクライアントからの
  INSERT・UPDATE 権限を与えていない。参加者かどうか、幹事かどうかを毎回そこで見る
- **参加はあいことば経由だけ。** `members` に直接 INSERT できないので、
  `trip_id` を知っているだけでは参加者になれない
- **購読するのは `rounds` の1行だけ。** チャンネルは1本
- **Realtime が落ちても止まらない。** 購読には必ずポーリングの保険が付いている。
  会場のWi-Fiで WebSocket が切れる前提

### C（体力・混雑・再構成）
- `lib/model.ts` の `simulate` と `proposeRevision` が境界。
  戻り値の形（`SimResult` / `Revision`）を保てば中身は全部差し替えてよい
- `K` が係数、`INITIAL_HP` / `INITIAL_MP` が初期値
- `MIN_END_HP` / `MIN_TROUGH_HP` は再構成案に求める余裕。予測が外れる分を残している
- `lib/spots.ts` の `crowdByHour` は時間帯別の推定値。リアルタイムではない。
  ここに天候と自アプリ利用者の位置分布を足す
- `travelMinutes` は表に無い組を直線距離で近似している。経路APIに置き換える

## テスト

```bash
npm test
```

- `test/store.contract.ts` … **実装によらず変わってはいけない約束**。
  localStorage 実装・Supabase 実装・遅延読み込みの包み、の3つすべてに同じものを当てる。
  実装を足すときは harness を1つ渡すだけでよい
- `test/pglite-client.ts` … PGlite（WASM の PostgreSQL 18）に `SupabaseLike` をかぶせたもの。
  作り物ではなく、`supabase/migrations` の SQL を**本物の PostgreSQL に流して**テストしている。
  RLS も RPC も本物
- `test/sql.test.ts` … アプリを通さずに何ができてしまうかを見る。
  票が読めないことは UI では確かめようがない
- `test/store.live.test.ts` … 本物の Supabase に同じ契約テストを流す。
  `DOCHU_LIVE_TEST=1` と URL/KEY を設定したときだけ走る

**PGlite で再現できないのは Realtime の push だけ。** そこはポーリングの保険が効くので
落ちていても動くが、実機で一度は通しておくこと。

## デモモード

ホームのあいことば欄に **`みちゆき`**（`NEXT_PUBLIC_DEMO_CODE`）を入れると入る。

企画書の「早送りシミュレーションが必須。会場で歩き回れないため」がこれ。
画面の下に操作卓が出て、以下を触れる。

| つまみ | 何が変わる |
|---|---|
| 時刻スライダー／再生／速さ | `useClock()` が返す「いまの分」。**全画面が同時に動く** |
| 天気（降っていない・小雨・本降り）／気温 | `simulate` の `environment`。ゲージと道程の数字がその場で変わる |
| 位置はモック / 実機 | 現在地の出どころ。GPSが不安定でも時計から作れる |

デモを抜けると実時計に戻る。デモ用の分岐はアプリ側に一切書いていない
（`useNow()` を `useClock()` に置き換えただけ）。

## 位置と地図

- `lib/location.ts` … 位置の源。実機の GPS と、デモの時計、どちらも同じ形
- `lib/visits.ts` … 実測。どこに何分いたか、どれだけ歩いたか。
  **「もう動かせない予定」は時計ではなく位置から決める**
- `components/Map.tsx` … 地図。外部タイルを読まないので会場Wi-Fiが死んでも出る。
  タイル地図に替えるときはこのファイルの中だけで済む

歩数そのものは Web では取れないので、GPS の移動距離で代えている。

## 見た目をいじるとき

`/style` を開く。色・文字・余白・ゲージ・道程・地図・割り込み（カードとロック画面風）・
ボタン・せーのの選択肢が、全部の状態で1画面に並ぶ。
`app/globals.css` を書き換えると同時に変わる。

- 色と余白のトークンは `app/globals.css` の `:root` 2箇所にまとまっている
- 画面（`app/`）はデータの出し入れ、部品（`components/`）は見た目だけ、と分けてある
- `/style` はデータを取りに行かないので、壊しても本番の画面に影響しない

## 設計上、崩してはいけない点

1. **ダメージは事前に出す。** 事後の「−30」は不快を可視化するだけ。
   `Track` が未来の区間の増減を先に描いているのはこのため
2. **落とすときは必ず言う。** `proposeRevision` は行き先を落とす案に重い罰則をかけ、
   並べ替えと短縮で足りるならそちらを選ぶ。落とす場合は文面の先頭で明示する
3. **効果が無いことを効果があるように書かない。** 混雑の改善は、
   元の時刻より実際に下がったときだけ文面に出す
4. **呼び出しは1日5回まで。** `callsUsed` が上限に達したら割り込みを出さない
5. **パーティでは個人を出さない。** ゲージは一番きつい人（`staminaFactor` の最大）に
   合わせて計算し、表示は「パーティに1人、限界が近い人がいます」だけ

## せーのの数値

`vetoCap(選択肢の数)` が1人あたりの上限。上限が無いと全滅が通常ケースになる。
一様ランダムでの実測（4000回）:

| 選択肢 | 人数 | 上限 | 全滅率 |
|---|---|---|---|
| 4 | 5 | 1 | 約25% |
| 4 | 10 | 1 | 約78% |
| 6 | 20 | 2 | 約100% |

**デモの本番は5〜7人でやること。** 会場全員を入れると必ず全滅し、
「反対ゼロ」という売りが毎回「妥協点」に化ける。
全滅時は反対が最少のものを妥協点として出す（`kind: "compromise"`）。設計通りの挙動。

## まだ無いもの

- 歩数計との連携（歩行距離は GPS から出している）
- Push通知（iOS はホーム画面に追加しないと飛ばない。画面内の割り込みが本線）
- `/public/icon-192.png` と `/icon-512.png`（manifest が参照している）
- 写真（道中記に置き場所だけ作ってある）
- **自アプリ利用者の位置分布による混雑補正。** 人数が要るので当日は効かない
- **道中を終える導線。** `store.finishTrip(id)` は用意したが、押す場所がまだ無い。
  これを呼ばないと `getLastFinished()`（ホームの「前の道中」）が永久に空のまま
- **待合を閉じるボタン。** `store.setRoomLocked(id, true)` も同じく、押す場所が無い
- **あいことばの総当たり対策。** 12000通りなので、機械的に総当たりされれば入られる。
  部屋の寿命を短くする以外の手当ては入れていない
- Realtime の push を実機で通すこと（ポーリングの保険は効いている）
